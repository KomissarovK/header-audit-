# Header Audit

Небольшая утилита для первичной проверки настроек безопасности веб-приложений. Она читает сохранённый HTTP-ответ и готовит Markdown-отчёт с результатами, пояснениями и рекомендациями. В проекте есть два синтетических образца одного HTTPS-ответа до и после настройки заголовков.

## Запуск

Понадобится Python 3.10 или новее. Дополнительные библиотеки не нужны. Выполни из папки проекта на Kali Linux или в терминале с доступным `python3`:

```bash
python3 header_audit.py examples/before.http --scheme https --output before.md
python3 header_audit.py examples/after.http --scheme https --output after.md
```

На Windows замени `python3` на `py -3`. Для повторного запуска выбери новое имя отчёта. Готовые результаты для обоих входов можно посмотреть в [examples/before.md](examples/before.md) и [examples/after.md](examples/after.md).

## Как работает проверка

1. Скрипт читает статус ответа и заголовки до первой пустой строки. Имена заголовков приводит к нижнему регистру, а повторяющиеся строки сохраняет отдельно.
2. Для каждого заголовка применяет правило из таблицы ниже. Повторяющиеся строки отправляет на ручную проверку, поскольку правила их обработки зависят от заголовка.
3. Записывает Markdown-таблицу. Значения заголовков, cookies и содержимое ответа в отчёт не попадают.

| Заголовок | Что проверяет скрипт |
| --- | --- |
| `Strict-Transport-Security` | Для HTTPS ищет одно положительное значение `max-age`. Остальные директивы оставляет для ручной проверки. |
| `X-Content-Type-Options` | Сверяет значение с `nosniff`. Тип содержимого проверяется отдельно вручную. |
| `Referrer-Policy` | Сверяет одиночное значение со списком из четырёх консервативных политик. Если есть список через запятую, предлагает проверить его вручную. |
| `Content-Security-Policy` | Проверяет наличие непустой политики. Её применимость и эффективность оцениваются вручную. |

Вход — один текстовый HTTP-ответ в UTF-8 с видимой строкой статуса вроде `HTTP/1.1 200 OK`. Схему запроса нужно передать явно. Программа работает с локальным файлом, без сетевых запросов. Для оценки приложения используй контекст ответа, например его тип содержимого и назначение страницы. Отсутствие заголовка в одном ответе само по себе не подтверждает уязвимость приложения.

## Что разобрать перед собеседованием

- Открой [header_audit.py](header_audit.py) и проследи путь одного заголовка от текстового файла до строки отчёта.
- В копии `examples/after.http` поменяй `max-age=31536000` на `max-age=0`. Предскажи результат, запусти проверку и объясни разницу.
- Для своего первого коммита добавь в README короткий разбор одного наблюдения: что было в ответе, какая настройка изменилась и как ты проверил результат.

Основа правил — [OWASP HTTP Headers Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/HTTP_Headers_Cheat_Sheet.html).
